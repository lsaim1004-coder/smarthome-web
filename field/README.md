# 현장 키트 — 방문 전에 다 만들어 가고, 현장에서는 꽂기만 한다

고객 집에서 HA 를 손으로 설치하면 안 된다. 도커 깔고 컨테이너 받고 통합 붙이다 보면
**반나절이 그냥 간다.** 고객이 옆에서 지켜보고 있으면 더 느려지고, 막히면 물어볼 곳도 없다.
(집 Wi-Fi 를 쓰니 노트북으로 검색은 되지만, 남의 집 거실에서 오래 헤매는 건 그 자체로 신뢰를 깎는다.)

**원칙: 집에서 미리 만들어 둔 미니PC 를 들고 가서 꽂는다. 현장 작업은 기기 페어링과 자동화뿐이다.**

| | 집에서 (미리) | 현장에서 |
| --- | --- | --- |
| OS·도커 설치 | ✅ | — |
| HA·Matterbridge·MQTT 기동 | ✅ | — |
| 계정 연동(ThinQ·샤오미) | — | ✅ 고객 계정이라 현장에서만 |
| 기기 페어링 | — | ✅ |
| 자동화·대시보드 | 템플릿까지 ✅ | 집에 맞게 수정 |

## 준비물

| | |
| --- | --- |
| 미니PC | 8GB/256GB. 알리 N100 약 13만(PoC) — [견적.md 3장](../docs/견적.md) |
| USB 동글 | Zigbee/Thread. **미니PC 에 꽂아 둔 채로 간다** |
| 맥북 | M2. `ssh`·브라우저만 있으면 된다 |
| 유선 랜선 | 1.5m. 고객 공유기에 직결하면 Wi-Fi 설정 단계를 건너뛴다 |
| 라벨 | 미니PC 뒷면에 세대 번호·설치일 |

## 1. 집에서 (한 번만, 40분)

```bash
# 미니PC 에 Debian 12 설치 후, 맥북에서
ssh <user>@<미니PC-IP>
curl -fsSL https://raw.githubusercontent.com/lsaim1004-coder/smarthome-web/main/field/setup-ha.sh | sudo bash
```

끝나면 `http://<미니PC-IP>:8123` 에서 HA 온보딩 화면이 뜬다. 여기까지가 집에서 할 일이다.

**이미지를 미리 받아 두는 것이 핵심이다.** 고객 집 인터넷이 느리면 컨테이너 내려받기만 20분이 걸린다.
`setup-ha.sh` 는 `docker compose pull` 까지 끝내므로 현장에서는 네트워크를 거의 쓰지 않는다.

## 2. 현장에서 (10분이면 HA 가 뜬다)

1. 미니PC 를 고객 공유기에 **랜선으로** 꽂고 전원
2. 맥북을 같은 Wi-Fi 에 붙이고 `http://homeassistant.local:8123`
   (안 뜨면 공유기 관리화면이나 `nmap -sn 192.168.0.0/24` 로 IP 확인)
3. 온보딩 → 위치·단위 설정
4. 계정 연동은 **고객이 직접 비밀번호를 입력**하게 한다. 내가 받아 적지 않는다

## 3. 막히면

맥북에서 Claude Code 로 물어보면 된다. 그때 **로그를 붙여넣지 말고 이 명령의 출력을 보여주는 편이 빠르다.**

```bash
bash field/collect.sh          # 상태 한 장으로 요약
```

## 왜 Docker 인가 (HAOS 가 아니라)

HA 공식은 HAOS(전용 OS)를 권하지만 현장 운영에는 Docker 가 낫다.

- **미니PC 한 대에 HA + Matterbridge + MQTT 를 같이 올린다.** HAOS 애드온으로도 되지만
  버전·백업을 compose 파일 하나로 관리하는 쪽이 세대가 늘었을 때 관리된다
- **세대마다 똑같은 상태로 만들 수 있다.** compose 파일이 곧 설치 사양서다
- **맥북에서 똑같이 띄워 미리 연습할 수 있다** — 이미지가 arm64 를 지원한다

단점: HAOS 의 원클릭 백업·애드온 스토어를 못 쓴다. 백업은 `field/backup.sh` 로 대신한다.
